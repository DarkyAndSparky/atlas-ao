# Атлас Аллодов

Фан-вики/интерактивная карта аллодов — неофициальный проект энтузиастов,
не связан с разработчиком игры. Express + SQLite (`node:sqlite`) на
бэкенде, ванильный JS без сборщика на фронтенде.

## Структура

## Возможности

- **Карта** с перетаскиваемыми метками островов, рисованием (линии/стрелки/
  фигуры/текст/украшения — компактная панель инструментов справа), масштабированием.
- **Атлас (вики-список)**, страница острова с локациями, галереей, картой
  локаций.
- **Rich-text** в описании/истории острова: `**жирный**`, `*курсив*`,
  `@Название` — ссылка на другой остров с автокомплитом по вводу.
- **Черновики острова** — название/описание/история редактируются
  отдельно от опубликованной версии, применяются явной кнопкой
  «Опубликовать», можно свернуть и вернуться позже или отклонить.
- **Разрешение конфликтов** — если поле кто-то уже сохранил, пока вы его
  редактировали, при попытке сохранить — обе версии рядом и явный выбор,
  ничего не перезаписывается молча.
- **Массовые операции** — выделение нескольких островов на карте,
  групповая смена тега или сборка в архипелаг.
- **Хронология** (мир + по острову), **источники** с привязками к
  островам/локациям, **архипелаги**.
- **Лента «последние изменения»** по всему сайту — фильтры по острову/
  автору, построчный diff (что именно поменялось).
- **Настоящие URL** на каждую страницу (`/allod/:id/:slug`, `/wiki`,
  `/timeline`...) — можно скопировать ссылку, работают кнопки браузера
  «назад»/«вперёд». Динамические meta/OG-теги для страниц острова.
- **Роли**: гость (только чтение) / редактор / администратор.
  Редактора можно ограничить конкретными проектами. Мягкая блокировка
  аккаунта (обратимо, действует немедленно — обрывает все текущие
  сессии), «последний вход», принудительный сброс пароля.
- **Гостевая форма «Сообщить об ошибке»** — единственная публичная точка
  записи на сайте, с отдельным строгим rate-limit; очередь для админа.
- **Полнотекстовый поиск** (FTS5), **бэкапы** (обычные и полный архив
  БД+файлы, по расписанию и вручную), **экспорт/импорт**.
- Все интерактивные диалоги — стилизованные модалки в цветах сайта, ни
  одного браузерного `prompt()`/`confirm()`/`alert()`.

## Запуск

### Быстрый способ — через скрипты

**Windows:** дважды кликните `install.bat` (один раз — и при каждом
обновлении зависимостей, скрипт сам определяет, нужно ли переустанавливать),
затем `start.bat` каждый раз, когда хотите открыть сайт. Браузер откроется
автоматически на `https://localhost:9311`.

**Linux/macOS:** в терминале выполните `./install.sh` один раз, затем
`./start.sh` для запуска. Если файлы не запускаются как исполняемые —
`chmod +x install.sh start.sh` один раз.

Оба скрипта поднимают HTTPS сами, без Docker — при первом запуске сервер
сгенерирует самоподписанный сертификат (кэшируется в `server/.https-cert/`,
не коммитьте эту папку), браузер один раз спросит подтверждение — это
ожидаемо для self-signed. Порты можно поменять переменными окружения
`ATLAS_HTTPS_PORT`/`ATLAS_HTTP_REDIRECT_PORT` (по умолчанию 9311/9312).

При самом первом запуске на пустой базе сервер сам создаёт аккаунт
`admin` со **случайно сгенерированным** паролем — смотрите баннер в
консоли при старте (дублируется в `server/.bootstrap-password`), пароль
нужно будет сменить при первом входе.

### Вручную

Нужен установленный Node.js (22.5 или новее — используется встроенный модуль `node:sqlite`,
поэтому никакой компиляции нативных модулей не требуется, ничего кроме Node.js ставить не нужно).

```bash
cd atlas-server/server
npm install      # один раз, ставит express, multer и т.д.
node server.js
```

Откройте в браузере: **http://localhost:4173** — это самый простой запуск,
без HTTPS вообще (голый HTTP). Чтобы получить HTTPS так же, как в
`start.sh`/`start.bat` (самоподписанный сертификат, редирект с HTTP), задайте
переменные окружения:

```bash
ATLAS_NATIVE_HTTPS=1 ATLAS_HTTPS=1 node server.js
```

Тогда сервер слушает `https://localhost:9311`, а `http://localhost:9312`
редиректит на него.

При первом запуске автоматически создастся файл `server/atlas.db` и в него
засеются все острова из `seed-data.json`. Дальше все правки живут в этой
базе — `seed-data.json` больше не используется.

### Импорт / экспорт
- **«Экспорт»** в шапке скачивает текущее содержимое базы как `.json`
  (можно использовать как бэкап).
- **«Импорт»** (только вошедшим в аккаунт) заменяет содержимое базы
  данными из выбранного `.json`-файла того же формата.
- Для переноса **самого файла БД целиком** — `GET /api/backup/download`
  и `POST /api/backup/restore` через «⚙ Настройки» → «Резервные копии».

Подробнее обо всех возможностях — `doc/index.html` (открывается прямо
в браузере, без запущенного сервера).

## HTTPS и Docker

HTTPS сервер терминирует **сам**, без реверс-прокси (Caddy/nginx) — см.
`server/certs.js`. Один и тот же механизм работает одинаково что при
`node server.js`, что при `start.sh`/`start.bat`, что в Docker: разница
только в том, откуда берётся сертификат.

- **Самоподписанный** (по умолчанию везде, кроме публикации) — сервер сам
  генерирует его при первом запуске (через `openssl`, если он есть в PATH,
  иначе через npm-пакет `selfsigned`) и кэширует на диске, чтобы браузер не
  просил заново подтверждать исключение при каждом перезапуске.
- **Настоящий** (для публикации в интернете) — сервер ничего не выпускает
  сам, просто читает готовые `fullchain.pem`/`privkey.pem` из
  `ATLAS_CERT_FILE`/`ATLAS_KEY_FILE`. Кто и как выпустил эти файлы —
  неважно, обычно это [certbot](https://certbot.eff.org/) (Let's Encrypt).

### Локальный запуск в Docker (HTTPS на самоподписанном сертификате)

```bash
cp .env.example .env
# по желанию поменяйте в .env:
#   ATLAS_HTTPS_PORT=9311
#   ATLAS_HTTP_REDIRECT_PORT=9312

docker compose -f docker-compose.local.yml up -d --build
```

Откройте `https://localhost:9311` — браузер предупредит про
самоподписанный сертификат, это ожидаемо, жмите «продолжить»/добавьте
исключение. HTTP-порт (`9312` по умолчанию) тоже слушает — но только чтобы
редиректнуть на HTTPS. Тот же самоподписанный сертификат работает и по IP
из локальной сети (например, `https://192.168.1.5:9311`).

Данные — в именованных Docker-томах (`atlas-db`, `atlas-uploads`,
`atlas-backups`), переживают пересборку. Сертификат — тоже в отдельном томе
(`atlas-https-cert`), поэтому не перегенерируется при каждом `up --build`.

Остановить: `docker compose -f docker-compose.local.yml down` (добавьте
`-v`, если нужно ещё и стереть базу/загрузки/бэкапы/сертификат).

Логи: `docker compose -f docker-compose.local.yml logs -f app`.

### Публикация с настоящим HTTPS (домен + Let's Encrypt через certbot)

Нужен настоящий домен с DNS, указывающим на этот сервер, и открытые наружу
порты 80/443. Сертификат выпускает и продлевает **certbot на хосте**
(снаружи Docker) — `docker-compose.yml` только читает готовые файлы.
Контейнер останавливается штатно по `SIGTERM` (см. `stop_grace_period` в
`docker-compose.yml`), логи ротируются автоматически (`max-size: 10m`,
`max-file: 5`).

```bash
cp .env.example .env
# впишите в .env: SESSION_SECRET — сгенерировать: openssl rand -hex 48

mkdir -p certs acme-webroot

# 1) первый запуск — ещё без сертификата, только чтобы поднялся редирект-сервер
#    на порту 80 (certbot будет стучаться на него для HTTP-01-проверки)
docker compose up -d --build

# 2) выпуск сертификата — certbot кладёт временный файл в acme-webroot,
#    наш редирект-сервер на порту 9312/80 отдаёт его как есть (см. server.js:
#    serveAcmeChallengeOrRedirect), certbot проверяет и выпускает сертификат
sudo certbot certonly --webroot -w ./acme-webroot -d atlas.example.com \
  --email you@example.com --agree-tos --non-interactive

# 3) скопировать выпущенный сертификат туда, где его ждёт контейнер
sudo cp /etc/letsencrypt/live/atlas.example.com/fullchain.pem ./certs/
sudo cp /etc/letsencrypt/live/atlas.example.com/privkey.pem ./certs/
sudo chmod 644 ./certs/*.pem

# 4) перезапустить, чтобы сервер подхватил сертификат (он читается один раз при старте)
docker compose restart app
```

Продление (certbot сертификаты Let's Encrypt живут 90 дней) — настройте
`cron`/systemd timer на хосте:

```bash
certbot renew --deploy-hook "cp /etc/letsencrypt/live/atlas.example.com/*.pem /path/to/atlas-server/certs/ && cd /path/to/atlas-server && docker compose restart app"
```

Что при этом происходит:
- **app** — единственный контейнер, Node.js-сервер сам терминирует HTTPS
  (непривилегированный пользователь; порты 80/443 наружу мапятся на
  непривилегированные 9312/9311 внутри контейнера). База, `uploads/`,
  `backups/` — в именованных Docker-томах, переживают пересборку.
- Приложение включает `ATLAS_HTTPS=1` — куки сессии становятся `Secure`
  (работают только по HTTPS).

Обновление после `git pull` (сертификат не трогает, он в отдельной папке,
не в образе):
```bash
docker compose up -d --build
```

Логи: `docker compose logs -f app`.

## Безопасность и обслуживание

- **Дефолтный аккаунт при первом запуске** — `admin` со случайно
  сгенерированным паролем (не захардкожен), печатается крупным баннером в
  консоль, дублируется в `.bootstrap-password` рядом с базой. Обязательная
  смена пароля при первом входе.
- **Rate-limit на логин — по IP И по аккаунту независимо** (5 неудачных
  попыток → блокировка на 5 минут по любому из двух ключей) — защищает и
  от подбора пароля к одному аккаунту с ротацией IP, и от перебора
  логинов с одного IP. Плюс общий лимит на весь `/api` (300 запросов/мин
  по умолчанию, `ATLAS_RATE_LIMIT_MAX`/`_WINDOW_MS`).
- **Пароль редактора — не короче 8 символов.**
- **Роли**: гость (только чтение) / редактор / администратор. Редактора
  можно ограничить конкретными проектами (проверяется на бэкенде на
  каждой мутирующей операции, не только скрыто в интерфейсе) —
  «⚙ Настройки» → «👤 Пользователи». Мягкая блокировка аккаунта
  (обратимо, немедленно обрывает все текущие сессии заблокированного —
  сессии хранятся в той же БД, не в памяти процесса). Последнего
  оставшегося администратора нельзя ни удалить, ни понизить в роли, ни
  заблокировать через сайт (см. ниже про `npm run reset-password`).
- **Секрет сессии** генерируется автоматически при первом запуске и
  сохраняется в `server/.session-secret` — не публикуйте этот файл и не
  коммитьте его в git. В Docker-режиме вместо файла используется
  переменная окружения `SESSION_SECRET`.
- **Сессии хранятся в той же SQLite-базе** (таблица `sessions`), не в
  памяти процесса — вход не слетает при перезапуске сервера.
- **Права на файл БД — `0600`**, только владелец процесса (в БД — хэши
  паролей пользователей).
- **Constant-time проверка пароля** даже для несуществующего логина —
  нельзя определить по времени ответа, существует ли аккаунт.
- **Security-заголовки** (`helmet`): строгий Content-Security-Policy (без
  inline-скриптов), `X-Content-Type-Options`, защита от clickjacking; при
  HTTPS (`ATLAS_HTTPS=1`) дополнительно `Strict-Transport-Security` и
  secure-куки.
- **Graceful shutdown** — сервер штатно завершает работу по `SIGTERM`/
  `SIGINT` (доотдаёт открытые запросы, финальный WAL-checkpoint), не
  падает от одного необработанного исключения в асинхронном роуте
  (глобальный `unhandledRejection`/`uncaughtException`-перехватчик).
- **Если забыли все пароли или нужно удалить чужой аккаунт без доступа к сайту**:
  ```bash
  cd atlas-server/server
  npm run reset-password
  ```
  Команда покажет список аккаунтов и даст удалить конкретный (по имени)
  либо все сразу (`all`) — тогда при следующем запуске сервер снова сам
  создаст `admin` со свежим случайным паролем. Данные островов не затрагиваются.
- **Резервная копия базы**:
  ```bash
  cd atlas-server/server
  npm run backup
  ```
  Копия с таймстампом появится в `atlas-server/backups/`.
- **Загружаемые фото** автоматически уменьшаются и пережимаются (длинная
  сторона до 1920px, качество ~82%), если это уменьшает размер файла —
  через `sharp`. Проверяются по содержимому, не только по заголовку.
- **Загружаемые SVG санитизируются через DOMPurify** (allowlist-подход,
  не blacklist-регексы) — `USE_PROFILES:{svg:true, svgFilters:true}`.
- При удалении картинки/острова физические файлы в `uploads/` тоже
  удаляются — мусор не копится.
- **Воспроизводимые сборки**: `package-lock.json` закоммичен, CI и
  `Dockerfile` ставят зависимости через `npm ci`, а не `npm install`.

Полная история находок из аудита трёх похожих проектов (что проверили,
что оказалось уже закрыто, что перенесли) — в приложении к
`atlas-roadmap.md`.
