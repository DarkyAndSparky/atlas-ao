# Атлас Аллодов

Локальный сайт-атлас: глобальная карта с островами-аллодами, страницы островов
и локаций с описанием/историей/галереей, встроенный редактор с входом по паролю.
Данные хранятся в SQLite на диске — переживают перезапуск сервера и работают
из любого браузера на этом компьютере.

Версия: см. файл `VERSION`. Полная документация по использованию — `doc/index.html`
(откройте прямо в браузере, сервер для этого не нужен).

> **Это ветка разработки (`dev`)** — полная, с тестами (`server/test/`),
> UI/e2e-тестами (`e2e/`) и CI (`.github/workflows/`). Чистая релизная сборка
> без всего этого — в ветке `main`.

## Тесты

**Быстрый способ — через скрипты** (аналогично install/start):

- `test.bat` / `test.sh` — весь набор: сначала бэкенд, потом UI/e2e (ставит зависимости при первом запуске, e2e ещё и скачивает браузер — может занять пару минут)
- `test-backend.bat` / `test-backend.sh` — только бэкенд (быстро, без браузера)
- `test-e2e.bat` / `test-e2e.sh` — только UI/e2e

**Бэкенд** (встроенный `node:test`, без внешних зависимостей):
```bash
cd server
npm test
```
Проверяет весь API: авторизацию и rate-limit, острова, локации и их сортировку,
галерею (включая проверку поддельных файлов), импорт/экспорт, полный бэкап БД.
Работает на изолированной временной базе — `atlas.db` не трогает.

**UI/e2e** (Playwright, отдельный пакет — не тянется при обычной установке):
```bash
cd e2e
npm install
npm run install-browsers
npm test
```
Поднимает настоящий сервер на изолированной базе и прогоняет реальный браузер
по карте, странице острова, вики-каталогу, переключателю проектов,
drag-and-drop и мобильному тач-управлению. Подробности — `e2e/README.md`.

## Безопасность и обслуживание

- **Секрет сессии** генерируется автоматически при первом запуске и сохраняется в
  `server/.session-secret` — не публикуйте этот файл и не коммитьте его в git.
  В Docker-режиме вместо файла используется переменная окружения `SESSION_SECRET`.
- **Сессии хранятся в той же SQLite-базе** (таблица `sessions`, `server/sessionStore.js`),
  а не в памяти процесса — вход не слетает при перезапуске сервера, и процесс не
  копит утечку памяти на долгой работе (дефолтный `MemoryStore` у express-session
  как раз про это предупреждает).
- **Вход защищён от перебора пароля**: после 5 неудачных попыток IP блокируется на 5 минут.
- **Пароль редактора — не короче 8 символов.**
- **Многопользовательские аккаунты**: любой вошедший редактор может пригласить
  ещё редакторов и удалять чужие аккаунты через панель «Настройки» → «👤 Редакторы».
  Все аккаунты равноправны, отдельной роли «администратор» нет. Удалить
  последнего оставшегося через сайт нельзя (см. ниже про `npm run reset-password`).
- **Security-заголовки** (`helmet`): строгий Content-Security-Policy (без inline-скриптов —
  весь UI переведён на `addEventListener`, никаких `onclick="..."` в разметке),
  `X-Content-Type-Options`, защита от clickjacking; при работе по HTTPS (`ATLAS_HTTPS=1`,
  см. Docker-режим) дополнительно включаются `Strict-Transport-Security` и secure-куки.
- **Если забыли все пароли или нужно удалить чужой аккаунт без доступа к сайту**:
  остановите сервер и выполните
  ```bash
  cd atlas-server/server
  npm run reset-password
  ```
  Команда покажет список аккаунтов и даст удалить конкретный (по имени) либо
  все сразу (`all`) — тогда при следующем входе на сайте предложат создать
  первый аккаунт заново. Данные аллодов при этом не затрагиваются.
- **Резервная копия базы**:
  ```bash
  cd atlas-server/server
  npm run backup
  ```
  Копия с таймстампом появится в `atlas-server/backups/`.
- **Полный экспорт/импорт базы через сайт** (кнопки в шапке при входе в аккаунт):
  - «Экспорт» — скачивает JSON-содержимое всех таблиц (быстрый бэкап содержимого).
  - Для скачивания/восстановления **самого файла БД целиком** используются серверные
    маршруты `GET /api/backup/download` и `POST /api/backup/restore` — более надёжный
    способ перенести атлас на другой компьютер один файлом.
- **Загружаемые фото и PNG/JPEG/WebP автоматически уменьшаются и пережимаются**
  (длинная сторона до 1920px, качество ~82%), если это уменьшает размер файла —
  иначе оставляется оригинал. GIF не трогается. Работает через `sharp`.
- **Загружаемые картинки проверяются по содержимому**, а не только по заголовку —
  файл с поддельным расширением/MIME будет отклонён.
- **Загружаемые SVG очищаются от `<script>` и обработчиков `on*="..."`** через
  DOMPurify — на случай, если файл откроют напрямую по ссылке, а не через `<img>`.
- При удалении картинки из галереи физический файл в `uploads/` тоже удаляется —
  мусор не копится. При удалении острова целиком (кнопка в редакторе на странице
  острова) вместе с ним удаляются все его локации, галерея и файлы.
- **Воспроизводимые сборки**: `package-lock.json` закоммичен, CI и `Dockerfile`
  ставят зависимости через `npm ci`, а не `npm install`.

## Запуск

### Быстрый способ — через скрипты

**Windows:** дважды кликните `install.bat` (один раз), затем `start.bat` каждый раз, когда
хотите открыть сайт. Браузер откроется автоматически на `https://localhost:9311`.

**Linux/macOS:** в терминале выполните `./install.sh` один раз, затем `./start.sh` для запуска.
Если файлы не запускаются как исполняемые — `chmod +x install.sh start.sh` один раз.

Оба скрипта поднимают HTTPS сами, без Docker — при первом запуске сервер
сгенерирует самоподписанный сертификат (кэшируется в `server/.https-cert/`,
не коммитьте эту папку), браузер один раз спросит подтверждение — это
ожидаемо для self-signed. Порты можно поменять переменными окружения
`ATLAS_HTTPS_PORT`/`ATLAS_HTTP_REDIRECT_PORT` (по умолчанию 9311/9312).

### Вручную

Нужен установленный Node.js (22.5 или новее — используется встроенный модуль `node:sqlite`,
поэтому никакой компиляции нативных модулей не требуется, ничего кроме Node.js ставить не нужно).

```bash
cd atlas-server/server
npm install      # один раз, ставит express, better-sqlite3, multer и т.д.
node server.js
```

Откройте в браузере: **http://localhost:4173** — это самый простой запуск,
без HTTPS вообще (голый HTTP). Чтобы получить HTTPS так же, как в
`start.sh`/`start.bat` (самоподписанный сертификат, редирект с HTTP), задайте
переменные окружения:

```bash
ATLAS_NATIVE_HTTPS=1 ATLAS_HTTPS=1 node server.js
```

Тогда сервер слушает `https://localhost:9311`, а `http://localhost:9312`
редиректит на него.

При первом запуске автоматически создастся файл `server/atlas.db` и в него
засеются все 318 аллодов из `seed-data.json`. Дальше все правки живут в этой
базе — `seed-data.json` больше не используется.

## Как пользоваться

- **Карта**: колесо мыши — зум, перетаскивание фона — панорамирование.
- **Поиск и фильтры** в шапке — по названию, категории, фракции.
- **Клик по метке острова** — открывает страницу острова.
- Пока вы не вошли в аккаунт — сайт полностью «только для чтения»:
  ничего нельзя кликнуть на редактирование, панель неразмещённых островов скрыта.

### Редактор
1. Нажмите **«Войти»** в шапке.
   - При самом первом входе на этом сервере (аккаунтов ещё нет вообще) вас
     попросят придумать имя пользователя и пароль — это станет первым
     редактором, его хэш пароля сохранится в базе `atlas.db`.
   - При следующих входах — просто вводите имя пользователя и пароль.
   - Пригласить ещё редакторов (или удалить чужой аккаунт) может любой уже
     вошедший — через «⚙ Настройки» → «👤 Редакторы». Все аккаунты
     равноправны. Последний оставшийся через сайт удалить нельзя.
2. Нажмите **«Редактор»** — теперь можно:
   - кликом по тексту редактировать название/описание/историю острова;
   - слева появится список **неразмещённых островов** с кнопкой
     **«+ Новый остров»** — создаёт пустую карточку и сразу открывает её на
     заполнение; перетащите остров из списка на карту, чтобы поставить метку
     (позиция сразу сохраняется на сервере);
   - существующие метки можно перетаскивать, чтобы поменять позицию;
   - фракция/категория/климат/размер и архипелаг — тоже редактируются: клик
     по тегу предлагает список уже использующихся где-то в базе значений
     (чтобы не плодить варианты написания одной и той же фракции) либо можно
     вписать своё; если поле ещё не заполнено — рядом появляется призрачная
     кнопка «+ фракцию»/«+ категорию» и т.д.;
   - в сайдбаре справа так же кликом редактируются «Владелец», «Тип»,
     «Дополнение», «Сюжет» (обычный текст, без списка вариантов);
   - у фракции — своя иконка, если для неё есть запись в библиотеке
     («⚙ Настройки» → «🛡 Иконки фракций»; сопоставление по точному названию
     без учёта регистра); показывается рядом с тегом на странице острова и в
     заголовке группы в «Атласе островов»;
   - на странице острова справа вверху — кнопка **«✕ Удалить остров»**:
     безвозвратно удаляет остров вместе со всеми его локациями и галереей;
   - в галерее — кнопка «+» добавляет картинку **файлом** (загружается в
     `uploads/`) или по **ссылке (URL)**;
   - в блоке «Локации» — добавление/удаление локаций острова, у каждой своя
     страница с описанием и галереей;
   - слева внизу на самой карте — **панель рисования**: текстовые подписи,
     линии, прямоугольники, круги и **украшения** (готовые картинки — обломки,
     астральные аномалии, турели и т.д., плюс свои через «⚙ Настройки» → «🖼
     Украшения карты» — набор не зашит в код, это управляемая библиотека).
     Всё это — векторные SVG-объекты в тех же координатах, что и метки островов,
     поэтому подписи и фигуры панорамируются и масштабируются вместе с картой
     один в один, без «уплывания» и без размытия текста при зуме. Инструмент
     «✕» стирает пометку по клику. Пометки привязаны к текущему проекту
     (Аллоды Онлайн/Пираты/...).
   - при возврате на карту со страницы острова (например, кнопкой «Атлас» или
     через хлебную крошку) его маркер моргает и от него расходятся кольца —
     чтобы сразу было видно, где он, особенно если открывали остров из вики.
3. **«Выйти»** — завершает сессию, редактор снова скрыт.

### Импорт / экспорт
- **«Экспорт»** в шапке скачивает текущее содержимое базы как `.json`
  (можно использовать как бэкап).
- **«Импорт»** (только вошедшим в аккаунт) заменяет содержимое базы
  данными из выбранного `.json`-файла того же формата.

## HTTPS и Docker

HTTPS сервер терминирует **сам**, без реверс-прокси (Caddy/nginx) — см.
`server/certs.js`. Один и тот же механизм работает одинаково что при
`node server.js`, что при `start.sh`/`start.bat`, что в Docker: разница
только в том, откуда берётся сертификат.

- **Самоподписанный** (по умолчанию везде, кроме публикации) — сервер сам
  генерирует его при первом запуске (через `openssl`, если он есть в PATH,
  иначе через npm-пакет `selfsigned`) и кэширует на диске, чтобы браузер не
  просил заново подтверждать исключение при каждом перезапуске.
- **Настоящий** (для публикации в интернете) — сервер ничего не выпускает
  сам, просто читает готовые `fullchain.pem`/`privkey.pem` из
  `ATLAS_CERT_FILE`/`ATLAS_KEY_FILE`. Кто и как выпустил эти файлы —
  неважно, обычно это [certbot](https://certbot.eff.org/) (Let's Encrypt).

### Локальный запуск в Docker (HTTPS на самоподписанном сертификате)

Попробовать Docker-режим на своей машине — без домена и без Let's Encrypt,
но с настоящим HTTPS: в 2026 году это базовый минимум даже для локалки —
secure-куки, PWA-фичи и т.п. ведут себя иначе на http. Порт HTTPS и порт
HTTP-редиректа настраиваются (по умолчанию 9311 и 9312):

```bash
cp .env.example .env
# по желанию поменяйте в .env:
#   ATLAS_HTTPS_PORT=9311
#   ATLAS_HTTP_REDIRECT_PORT=9312

docker compose -f docker-compose.local.yml up -d --build
```

Откройте `https://localhost:9311` — браузер предупредит про
самоподписанный сертификат, это ожидаемо, жмите «продолжить»/добавьте
исключение. HTTP-порт (`9312` по умолчанию) тоже слушает — но только чтобы
редиректнуть на HTTPS, ходить по нему самому не нужно. Тот же
самоподписанный сертификат работает и по IP из локальной сети (например,
`https://192.168.1.5:9311` — открыть с телефона в той же Wi-Fi-сети).

Данные — в именованных Docker-томах (`atlas-db`, `atlas-uploads`,
`atlas-backups`), переживают пересборку. Сертификат — тоже в отдельном томе
(`atlas-https-cert`), поэтому не перегенерируется при каждом `up --build`.

Остановить: `docker compose -f docker-compose.local.yml down` (добавьте
`-v`, если нужно ещё и стереть базу/загрузки/бэкапы/сертификат).

Логи: `docker compose -f docker-compose.local.yml logs -f app`.

### Публикация с настоящим HTTPS (домен + Let's Encrypt через certbot)

Если нужно открыть Атлас с других устройств или из интернета — нужен
настоящий домен с DNS, указывающим на этот сервер, и открытые наружу порты
80/443. Сертификат выпускает и продлевает **certbot на хосте** (снаружи
Docker) — `docker-compose.yml` только читает готовые файлы.

```bash
cp .env.example .env
# впишите в .env: SESSION_SECRET — сгенерировать: openssl rand -hex 48

mkdir -p certs acme-webroot

# 1) первый запуск — ещё без сертификата, только чтобы поднялся редирект-сервер
#    на порту 80 (certbot будет стучаться на него для HTTP-01-проверки)
docker compose up -d --build

# 2) выпуск сертификата — certbot кладёт временный файл в acme-webroot,
#    наш редирект-сервер на порту 9312/80 отдаёт его как есть (см. server.js:
#    serveAcmeChallengeOrRedirect), certbot проверяет и выпускает сертификат
sudo certbot certonly --webroot -w ./acme-webroot -d atlas.example.com \
  --email you@example.com --agree-tos --non-interactive

# 3) скопировать выпущенный сертификат туда, где его ждёт контейнер
sudo cp /etc/letsencrypt/live/atlas.example.com/fullchain.pem ./certs/
sudo cp /etc/letsencrypt/live/atlas.example.com/privkey.pem ./certs/
sudo chmod 644 ./certs/*.pem

# 4) перезапустить, чтобы сервер подхватил сертификат (он читается один раз при старте)
docker compose restart app
```

Продление (certbot сертификаты Let's Encrypt живут 90 дней) — настройте
`cron`/systemd timer на хосте, который раз в день пытается продлить и, если
получилось, копирует файлы заново и рестартует контейнер:

```bash
certbot renew --deploy-hook "cp /etc/letsencrypt/live/atlas.example.com/*.pem /path/to/atlas-server/certs/ && cd /path/to/atlas-server && docker compose restart app"
```

Что при этом происходит:
- **app** — единственный контейнер, Node.js-сервер сам терминирует HTTPS
  (непривилегированный пользователь; порты 80/443 наружу мапятся на
  непривилегированные 9312/9311 внутри контейнера — процессу не нужны root-права).
  База, `uploads/`, `backups/` — в именованных Docker-томах, переживают пересборку.
- Приложение включает `ATLAS_HTTPS=1` — куки сессии становятся `Secure`
  (работают только по HTTPS).

Обновление после `git pull` (сертификат не трогает, он в отдельной папке,
не в образе):
```bash
docker compose up -d --build
```

Логи: `docker compose logs -f app`.
