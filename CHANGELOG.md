# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).
Версии — по внутренней схеме `vYYwWW-NN` (год-неделя-сборка).

Этот файл — единственный источник истины для истории изменений: раздел
«Последние изменения» на странице «О системе» (видна только вошедшим)
парсит именно его (`server/routes/system.js`), отдельного дублирующего
списка в коде нет.

**Каждый значимый коммит должен добавлять сюда запись.** Pre-commit хук
(`scripts/hooks/pre-commit`, ставится через `npm install` в `server/` →
`prepare`) напоминает об этом, если меняются файлы в `server/`,
`public/js/` или `public/*.html`, а `CHANGELOG.md` в этом же коммите не
тронут.

### Исправлено
- **Роадмап п.12: сайт зависал после восстановления из бэкапа/полного
  архива, требовался ручной перезапуск процесса.** `/api/backup/restore` и
  `/api/backup/restore-full` намеренно завершали процесс (`process.exit`)
  после перезаписи БД — под Docker (`restart: unless-stopped`) контейнер
  поднимался сам, а при обычном запуске (`node server.js`/`start.sh`/
  `start.bat`, без супервизора) сайт реально переставал отвечать до
  ручного вмешательства. Добавлен `server/restart.js`: перед выходом
  процесс теперь сам порождает detached-копию себя (тот же `process.argv`
  и окружение) и только потом завершается — новая копия успевает
  подняться и переоткрыть БД за секунду-две. Respawn НЕ включается внутри
  Docker (маркер `/.dockerenv`) — там перезапуск уже даёт restart-policy
  контейнера, и второй параллельный процесс на том же порту устроил бы
  гонку. Текст ответа API теперь честно отражает, что произойдёт
  (`respawn` / `docker` / ручной перезапуск, если respawn не удался).
  Проверено вживую (не только тестами с `ATLAS_TEST_NO_EXIT`): реальный
  локальный сервер, реальный `/api/backup/restore-full`, PID процесса
  меняется, сайт отвечает `200` и логин работает уже в новой копии в
  течение секунды после ответа API — без единого ручного действия.
  Полный бэкенд-сьют: 266/266.
- **П0 роадмапа: разделы вики (Атлас/Источники/Хронология/Архипелаги) не
  открывались вообще — ни через выпадающее меню «Вики ▾», ни кликом по
  логотипу.** Причина — `mapView.js` подключается в `index.html` раньше
  `wikiView.js`, а строка `document.getElementById('brand')
  .addEventListener('click', showWiki)` передавала прямую ссылку на
  функцию `showWiki`, разрешаемую немедленно, в момент выполнения
  верхнего уровня скрипта — на тот момент `showWiki` ещё нигде не
  определена → `ReferenceError`, обрывающий выполнение всего остального
  `mapView.js`. Из-за этого не выполнялся и следующий за ним `forEach`,
  вешающий обработчики клика на все четыре пункта выпадающего меню «Вики
  ▾» — они молча оставались без единого обработчика при каждой загрузке
  страницы, отсюда и «клик никуда не ведёт» без единой ошибки в логике
  `showWiki()`/CSS. Обёрнуто в `()=>showWiki()`, откладывающую разрешение
  имени до реального клика (когда все скрипты уже точно загружены).
  Воспроизведено и проверено вне браузера через jsdom + реальный локальный
  сервер: `ReferenceError` пропал, `#wikiView` получает класс `show`.
  Разблокирует весь e2e-сьют (десятки тестов упирались именно в это).
- Форма обязательной смены пароля требовала текущий (временный) пароль —
  избыточное трение, человек его секунду назад ввёл при входе. Убрано для
  форс-смены (`must_change_password=1`); добровольная смена пароля из
  настроек по-прежнему требует текущий, как и раньше.
- В форме обязательной смены пароля Tab уводил фокус на элементы шапки за
  затемнением (не было ловушки фокуса) — добавлена, Tab/Shift+Tab теперь
  циклируются только среди полей самой модалки.
- **Светлая тема была логически сломана и не соответствовала WCAG AA.**
  `--gold-bright` был ТЕМНЕЕ, чем `--gold` (наоборот, чем в тёмной теме) —
  кнопки на hover уходили в более грязный тон вместо того, чтобы
  «зажигаться». Контраст текста кнопки (обычное состояние) — 3.84:1,
  ниже порога AA (4.5:1) для мелкого жирного текста. Пересчитана вся
  золотая пара и базовые поверхности с проверкой контраста по формуле
  WCAG (не на глаз) — все критичные пары текст/фон теперь ≥4.5:1.
- Проход по всем 10 стартовым/установочным/тестовым скриптам
  (`install.bat/.sh`, `start.bat/.sh`, `test.bat/.sh`,
  `test-backend.bat/.sh`, `test-e2e.bat/.sh`): добавлен `setlocal` во все
  `.bat`-файлы (переменные вроде `ATLAS_OPEN_BROWSER` больше не могут
  протечь в родительскую сессию cmd, если скрипт вызовут через `call` из
  другого скрипта); `chcp 65001 >nul 2>&1` вместо `>nul` (глушим и stderr);
  везде, где скрипт может надолго зависнуть на `npm install`, теперь явное
  предупреждение «может занять минуту-другую, не закрывайте окно» —
  раньше это было только в `start.*`; отдельно выделено предупреждение
  про скачивание браузеров Playwright для e2e (`npm run install-browsers`)
  — это отдельная, гораздо более долгая загрузка (сотни МБ), которую
  раньше не отличали от обычной установки npm-пакетов; `test.bat`/
  `test-e2e.bat` теперь проверяют код выхода `install-browsers` (раньше
  тихо продолжали к тестам даже при неудачной установке браузеров);
  `test.bat` — исправлена одна ветка (неудачная установка зависимостей
  сервера), которая не делала `cd ..` перед выходом, в отличие от всех
  остальных веток ошибок в этом же файле — не влияло на поведение (скрипт
  всё равно завершался следующей командой), но было несогласованно.
- **Браузер открывался ДО того, как сервер реально начинал слушать порт.**
  `start.bat` вызывал `start "" "url"` строкой раньше `node server.js` —
  открывал вкладку сразу, независимо от готовности сервера. `start.sh`
  вместо этого гадал через `sleep 1.5` — на медленной машине или при первом
  запуске (засев 318 островов в БД) секунды полутора может не хватить.
  Теперь браузер открывает сам `server.js` изнутри колбэка `app.listen()` —
  единственный момент, когда сервер гарантированно готов принимать запросы
  (флаг `ATLAS_OPEN_BROWSER=1`, выставляется обоими стартовыми скриптами).

- Публичная кнопка-иконка смены темы (🌗) в шапке — раньше переключить
  тему можно было только через «⚙ Настройки», которая доступна лишь

  сценария: окно мгновенно закрывается (почти всегда Mark of the Web /

  Consolas/Lucida Console или открыть через Windows Terminal), первый
  запуск выглядит зависшим (на деле `sharp` скачивает нативный бинарник).
- Автоматические бэкапы по расписанию (`server/backupScheduler.js`) —
  раньше только вручную (кнопкой/`npm run backup`). Выключено по умолчанию,
  включается `ATLAS_AUTO_BACKUP=1` (+ опционально `ATLAS_AUTO_BACKUP_HOUR`,
  `ATLAS_AUTO_BACKUP_KEEP`). Без новых зависимостей — свой планировщик на
  `setInterval`, ротация старых копий (не трогает ручные бэкапы и
  pre-restore снимки — отдельный префикс имени файла). Заодно поймал и
  починил баг до того, как он попал в прод: `docker-compose`'s `${VAR:-}`
  подставляет пустую строку, а не отсутствие переменной — `Number('')`
  даёт `0`, что превратило бы дефолтный час в полночь вместо
  документированных 3.
- Дефолтный аккаунт `admin`/`admin0000` — защита от дурака: на свежей базе
  без единого пользователя сервер сам создаёт его при первом запуске, вместо
  открытого bootstrap-экрана «создайте первый аккаунт». Обязательная смена
  пароля при первом входе (`must_change_password` в БД, форма без кнопки
  «отмена», блокирует интерфейс, пока пароль не сменён) — распространяется
  и на любой аккаунт, который завёл администратор для другого человека
  (начальный пароль выбирал не сам пользователь). Проверено отдельным
  файлом тестов, включая явную проверку сценария «что будет, если удалить
  учётку admin» (можно, если это не последний оставшийся admin — сайт не
  осиротеет).
- Публичная мини-плашка внизу страницы (лицензия, автор, ссылка на GitHub,
  номер версии) — видна вообще всем посетителям, не только вошедшим. Новый
  публичный роут `GET /api/system/public` (без `requireAdmin`) отдаёт
  только безопасный минимум: версию, автора и ссылку на репозиторий

- Отдельная кнопка-переключатель для панели рисования (`🖌`) — раньше
  панель появлялась автоматически при включении режима редактора, теперь
  включается/выключается независимо.
- Инструмент рисования расширен: стрелка, многоугольник (клик за кликом,
  двойной клик/Enter — завершить, Esc — отмена), линия от руки (drag,

  последнего действия — кнопка и Ctrl+Z (создание/удаление/перемещение,

  Новая колонка `points` (JSON) в `map_annotations` — ADD COLUMN без
  пересоздания таблицы, т.к. на неё не распространялось старое
  CHECK-ограничение; протестировано и на схеме с `icon_url` без ролей,
  и вручную на старом дампе.
- Полный архив сайта: `GET /api/backup/download-full` /
  `POST /api/backup/restore-full` — база **и** все загруженные файлы
  (`uploads/`) одним `.zip`, не только `.db`. Раньше `restore` тащил
  только базу — ссылки в ней на `/uploads/xxx.jpg` после переезда на
  новую машину указывали в никуда. Новая зависимость `adm-zip` (0
  транзитивных зависимостей, чистый JS, без нативных биндингов — не
  усложняет Docker-сборку). Защита от zip-slip (путь `../` внутри архива
  не может выйти за пределы `uploads/`) — проверена не только логикой, но
  и намеренно сконструированным вредоносным архивом. При восстановлении
  снимок текущего состояния (БД + uploads) делается тем же способом, что
  и в обычном restore — «на всякий случай».
