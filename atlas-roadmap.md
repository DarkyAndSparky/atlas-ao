0. **Нерешённый кластер: `#wikiView`/`#sourcesView`/`#timelineView` не
   получают класс `show` после клика по разделам вики.** Затрагивает
   десятки e2e-тестов (`map.spec.js`, `wiki.spec.js`, `sources.spec.js`,
   `timeline.spec.js`, `wiki-dropdown.spec.js`, `projects.spec.js`,
   `search.spec.js`, `history.spec.js`, `recent-changes.spec.js` и др.) —
   клик по `[data-view="wiki"]` (через `#wikiDropdownBtn` или напрямую по
   `#brand`) не приводит к появлению класса `show`. Прочитал вручную весь
   путь клика (`wikiDropdown.js` → `mapView.js` → `showWiki()` в
   `wikiView.js`) — логически класс должен ставиться синхронно самой
   первой строкой функции, никакого явного условия/асинхронности не
   нашёл. Дальше без реальной консоли браузера (вкладка Console в
   Playwright-трейсе упавшего теста) диагностировать нельзя — либо
   где-то раньше по цепочке кидается необработанное исключение, либо
   обработчик клика вообще не навешивается. Отложено — трогать при
   следующем заходе на e2e, начать с открытия трейса любого из
   упавших тестов и снятия текста ошибки из Console.

1. **`e2e/global-setup.js` логинится как `admin/admin0000`, а сервер
   теперь генерирует случайный bootstrap-пароль при первом запуске**

## Перенесено из старого роадмапа (незакрытое)

2. **~~Второй, независимый блокер e2e: rate-limiter по IP валит почти весь сьют~~ — исправлено.**
   `server/security/rateLimiter.js` блокирует IP на 5 минут после 5
   неудачных попыток входа, лимит общий на весь процесс сервера и не
   сбрасывается между тестами. Сьют специально гоняет несколько тестов
   «неверный пароль» по всему прогону — как только с одного и того же
   `localhost` набралось 5 фейлов суммарно, **все последующие тесты**,
   которым нужен реальный логин (даже с верным паролем), стабильно
   валятся таймаутом на `actionTimeout` (~10-11с) — картина «первый тест
   зелёный, дальше всё красное», подтверждено логом реального прогона
   (228 тестов, 1 воркер). Добавлен `ATLAS_DISABLE_RATE_LIMIT=1` в
   `webServer.env` — только для e2e, в проде переменная не ставится,
   поведение блокировки не меняется.
   - **Отдельно стоит рассмотреть как прод-риск** (не блокер, но стоит
     занести в раздел «Критично» выше): блокировка по IP, а не только по
     аккаунту, значит один сотрудник, ошибившийся паролем 5 раз с общего
     офисного/NAT-адреса, блокирует на 5 минут вход **всем** остальным с
     того же IP. Стоит подумать, не сделать ли лимит только по аккаунту
     (`attemptsByTarget`), либо увеличить `MAX_ATTEMPTS` для IP-ключа
     отдельно от аккаунтного.

7. **~~CSRF-защита отсутствует~~ — исправлено.** Куки уже были

   отдаёт 403 при несовпадении; запросы вовсе без обоих заголовков
   (curl, серверные клиенты — CSRF там невозможен в принципе) не
   блокируются. Покрыто новым `server/test/csrf.test.js`.

     прогоне полного бэкенд-сьюта после этой правки:

        константу `MAX_TRACKED_KEYS` — это роняло **любую** попытку

## 🧪 Покрытие тестами — отдельный системный пункт

Регрессы последних сессий почти все живут на стыке фронтенда и реального
UI-потока, там, где e2e либо не существует, либо проверяет только
happy-path. Пока П0 не закрыт, ни один e2e-тест не подтверждён живым
прогоном вообще — часть этих дыр могла существовать уже давно незамеченной.

- **Нет `e2e/tests/drafts.spec.js`** — `server/test/drafts.test.js`
  покрывает API, но ни один e2e-тест не гоняет реальный поток черновика
  через UI. Отсюда пропущенные регрессы: удаление скриншота в режиме
  черновика не считается изменением («нечего сохранять»), плашка
  «ЧЕРНОВИК» не закреплена при скролле. Самый приоритетный пробел —
  учитывая объём находок именно здесь (см. п.25 выше).
- **Нет `e2e/tests/theme.spec.js`** — переключение светлая/тёмная тема
  не тестируется e2e вообще, при этом минимум 3 находки именно на теме
  (кнопка удаления острова, «неразмещённые острова», форма острова —
  п.17/18 выше).
- **Нет e2e на бэкап через UI** — `backup-*.test.js` гоняют бэкап
  напрямую через API/scheduler, кнопку «сделать бэкап» из настроек никто
  не кликает. Отсюда живой баг «бэкап не делался» невидим для сьюта
  (п.11 выше).
- **Нет e2e на сброс пароля** — отдельная кнопка не покрыта ни одним
  тестом (п.14 выше).
- **Нет общего smoke-теста** «пройтись по всем вкладкам и покликать
  видимые кнопки» — баг «кнопки не кликаются во всех вкладках» (п.15)
  в принципе не ловится точечными тестами по фичам, нужен отдельный
  обходной smoke-прогон.
- **Нет проверки устойчивости состояния при навигации** — иконки
  проектов слетают при переходе остров→вики и восстанавливаются после
  повторного клика (п.16). Под класс багов «состояние теряется между
  вью» сейчас нет вообще никакого паттерна тестов.
- **Нет `e2e/tests/decorations.spec.js`** — только `server/test/
  decorations.test.js`. Баг с правым кликом при размещении украшений —
  чисто фронтендовый (мышь/драг), бэкенд-тест его в принципе не поймает.

**Порядок действий**: сначала П0 (без него все e2e-тесты, включая новые,
не запускаются), потом — `drafts.spec.js` и `theme.spec.js` как
наивысший приоритет (больше всего необнаруженных регрессов), остальное —
по ходу Sprint 1.

## Как двигаться

1. Сначала П0 (иначе e2e нельзя гонять вообще).
2. Затем «Критично» — особенно CSRF, автобэкап и зависание после
   восстановления архива (риск потери данных/downtime).
3. Затем «Важно» — тут много пересекающихся тем (черновики+модерация
   правок читателей — фактически одна большая задача, п.22/25/28/29).
4. «Средне» и «Полировка» — по желанию, не блокируют публичный релиз.
